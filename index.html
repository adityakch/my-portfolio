/notes

Field notes

Short write-ups on the principles behind the work.

Prioritization

CVSS tells you how bad a bug could be. Not how likely it is to hurt you.

+

A backlog sorted by CVSS alone buries the vulnerabilities that attackers are actually using. I rank work with Qualys TruRisk and QDS, then adjust for three things: is there a public exploit, is it being exploited in the wild, and how critical is the asset.

An actively exploited CVE on an internet-facing server jumps the queue even if its base score is lower than a theoretical bug on an isolated workstation. That single rule does more for real risk reduction than any SLA chart.

Deployment

Fast patching needs a slow start

+

Speed comes from confidence, and confidence comes from rings. A patch goes to a small pilot ring first, then broader rings once telemetry looks clean. Every rollout has a written rollback plan before it starts.

Device targeting is automated too. Azure Automation runbooks read department and job title, then assign the right update ring, security policies and required apps. New devices land in the right place without anyone touching them.

Firmware

The Secure Boot certificate rollover of 2026

+

Microsoft's original Secure Boot certificates from 2011 began expiring in 2026. Devices that never receive the 2023 replacements can lose the ability to get future boot security updates.

Firmware-level changes are high stakes, so I treated this as a production change: staged rollout, validation on representative hardware, and change-control sign-off before each wave.

Validation

"Patched" is a claim. Telemetry is the evidence.

+

A deployment marked successful does not mean the vulnerable file is gone. I verify with Microsoft Sentinel endpoint data, chase down suspected false positives with the scanner team, and document a risk exception with compensating controls when a patch is not possible.

The result is a vulnerability report leadership can trust, which I publish as Power BI dashboards for security and reliability metrics.

Background

What software engineering taught me about security

+

Years of shipping APIs gave me habits I still use: validate every input (I built JSON Schema validators for exactly that), write regression tests before you trust a change, and block releases that fail quality gates like SonarQube.

Security automation is software. It deserves the same review, testing and version control as any product code.
